# >=3.3.15, not just >=3.2: this is the release that loosened checkov's own
# urllib3 pin to a floor instead of an exact version (see below). Without
# this explicit floor, pip's resolver is free to satisfy the asteval/urllib3
# floors below by backtracking checkov all the way down to 3.2.10 instead —
# technically valid, but ~340 releases of rule coverage and bugfixes worse,
# for the same or a worse security outcome. Confirmed by reproducing that
# backtrack locally before adding this line.
checkov>=3.3.15

# Transitive pins raised to clear known advisories in checkov's dependency
# tree. Dev-tooling only — the Lambda functions ship no bundled dependencies,
# so nothing here reaches a runtime.
#
# urllib3>=2.7.0 clears PYSEC-2026-141/1994/1996/1998/1999 in full — checkov
# 3.3.15 loosened its own urllib3 pin to a floor (>=1.26.20), so this
# resolves cleanly.
#
# asteval>=1.0.6, not >=1.0.9: checkov hard-pins asteval to an *exact*
# version at every release checked, including latest (3.3.16: ==1.0.6). No
# currently-supported checkov release accepts >=1.0.9. 1.0.6 clears
# PYSEC-2026-1195 and GHSA-vp47-9734-prjw; the one remaining advisory that
# needs 1.0.9 (GHSA-9w56-46f6-3qhx / CVE-2026-55244, same vulnerability
# under two IDs) is ignored explicitly in ci.yml's pip-audit step, not
# silently dropped — see the comment there and docs/threat-model.md's
# "Suppressed scanner checks" section.
urllib3>=2.7.0
asteval>=1.0.6
